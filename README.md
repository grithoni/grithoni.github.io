# grithoni · 项目展示

**网址：https://grithoni.github.io/**

四套智能辅助解纷系统的展示页。四套系统分别对应调解、中立评估、争议评审、仲裁四种解纷方式，做法一样：AI 起草与分析，程序计算与校验，最后由有权的人确认。

## 项目

按第三方在解纷中的作用由弱到强排列：

| 解纷方式 | 项目 | 简介 | 展示页 |
| --- | --- | --- | --- |
| 调解 | MedFlow · 调解智能辅助系统 | 按五个阶段、15 个环节辅助调解员，帮助双方找到都能接受、各有所得的方案；第三方促成协商，不替双方作决定 | [/medflow/](https://grithoni.github.io/medflow/) |
| 中立评估 | NeFlow · 知识产权纠纷中立评估在线平台 | 评估专家就知识产权纠纷给出评估意见，帮双方看清各自主张的强弱；意见无约束力，可转入和解 | 筹备中 |
| 争议评审 | DrbFlow · 在线争议评审平台 | 依据合同建立智能合约机制，实时监测履约，达到预设阈值时自动启动评审，及早化解履约争议 | [/drbflow/](https://grithoni.github.io/drbflow/) |
| 仲裁 | ArbFlow · 仲裁全流程智能辅助系统 | 依据《广州仲裁委员会仲裁规则（2026）》，每项待办是一条工作流，程序计算与大模型辅助结合；作出有约束力的裁决 | 筹备中 |

各项目源码不公开。展示页都是静态页面，不连接任何后台，页面中的人名、单位、金额均为示例。

## 目录结构

```
index.html     总入口页（直接在本仓库维护）
favicon.svg    总入口页图标
.nojekyll      让 GitHub Pages 原样发布文件
medflow/       MedFlow 介绍页（由项目仓库自动同步，不要在这里直接改）
```

## 更新方式

- **总入口页**：直接修改本仓库根目录的 `index.html`，推送到 main 后由 GitHub Pages 自动发布，一两分钟生效。
- **各项目的介绍页**：在项目仓库的 `site/` 目录里修改。项目仓库推送后，它的同步工作流把 `site/` 复制到本仓库对应的目录。同步只改该项目自己的目录，不动根目录和其他项目。在本仓库直接改项目目录的话，下次同步时会被覆盖。

## 添加一个项目

1. 在项目仓库建 `site/` 目录，放入介绍页（`index.html` 等）。
2. 复制 MedFlow 仓库的同步工作流 `.github/workflows/pages.yml`，把 `TARGET_DIR` 改成该项目的目录名（小写，如 `arbflow`）。
3. 在项目仓库设置 Secret `PAGES_TOKEN`：只授权本仓库、Contents 读写的 fine-grained token，各项目可共用一个。
4. 推送项目仓库，确认本仓库出现对应目录后，在总入口页把该项目的「展示页筹备中」改成链接，并更新上面的表格。
