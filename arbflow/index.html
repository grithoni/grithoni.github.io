01 / 理念

不猜时限、不造事实、不代裁判

仲裁文书直接关乎当事人重大财产处分，一旦出现虚构法条、错算期间或漏审请求，将直接引发司法撤裁或不予执行风险。ArbFlow 从根本上抛弃“端到端直接生成裁决书”的虚浮做法。

传统大模型生成
直接投喂卷宗，一键让模型生成整份裁决书。表面文辞通顺，实则法条编号虚构、事实段落张冠李戴、期限算错一天即遭撤销。
ArbFlow 示范实践
程序能算的纯代码计算；模型起草的逐段出处锁定；四重校验拦截任何幻觉；最终结果全部由有权的人逐项确认。
01 / 纯程序确定性

A 类待办零模型调用

起算日、工作日顺延、选定期限、仲裁费用测算等确定性程序，全部由纯程序算法精准复核，杜绝大模型推断日期。

02 / 工具沙箱隔离

智能体按段受控阅读

智能体步骤仅开放只读工具（分段阅卷、条文查阅、法定期限），禁止自由发散，抽取结论必须回注材料精确段号。

03 / 阻断性校验器

四重护栏拦截留痕

出处缺失剔除、金额与日期溯源、规则条文比对、请求防漏裁。拦截结果直接记入审计日志，失败副本绝不落库。

04 / 权责边界明确

四级主体人工确认

工作流在建议形成后必然暂停。仲裁秘书、仲裁庭、部门负责人、委员会主任在法定权限内各自确认，系统绝不代行权力。

02 / 全流程覆盖

10 个程序阶段 · 64 项标准工作流

从当事人申请准备，到立案、送达、组庭、审理、合议、核阅直至裁后程序，依据 2026 规则细化为 64 条可编排的工作流。点击下方阶段标签，查看各阶段的具体待办与行权主体。

03 / 校验护栏

四重防幻觉拦截网

大模型生成的内容在 ArbFlow 中只能作为“未决草稿”。任何建议进入人工决策界面之前，必须依次通过四层独立的程序校验器。

GUARD 01 / GROUNDING VERIFIER

材料出处比对与段号回溯

智能体分析输出的所有事实结论，必须标注材料段号出处（如 `[段3]`）。校验器自动将模型摘录与在案原文比对，凡未读到、对不上原文或虚构出处的，直接予以剔除。若全部结论均无据可循，整项待办 422 拦截。

校验逻辑：原文命中率 >= 80% 且段号有效；无据事实强制剥离，绝不混入裁判文书草稿。
GUARD 02 / VALUE & PROVENANCE

数值与日期严格溯源

严禁模型推断生效日期、答辩截止日或利息数额。所有期间计算统一调用内置日历引擎，严格遵循《广州仲裁规则》第 54 条顺延规则（遇周六、周日及法定节假日顺延至下一个工作日）。模型自拟日期直接拦截。

校验逻辑：日期、金额、期间须来自材料原文、程序参数或系统日期计算；自创推算一律阻断。
GUARD 03 / ARTICLE CONFORMITY

2026 规则条文反向核对

系统内置《广州仲裁委员会仲裁规则（2026）》及相关专门规则全库。模型在生成程序通知、审查意见或核阅建议时引用的每一条规则条号，均执行 block 级反向核验，引用未经知识库授权条文的立即阻断并审计留痕。

校验逻辑：引用依据范围白名单校验；材料中未出现、知识库亦无记载的虚构条文直接拦截。
GUARD 04 / STRUCTURAL INTEGRITY

裁决书结构规范与防漏裁

针对 S7/S8 裁决文书，解析开头、仲裁请求、事实认定、仲裁庭意见与裁决主文五个组成部分。程序逐项核对申请人各项仲裁请求是否均在主文中得到回应，防止遗漏请求（漏裁）或超出约定仲裁事项（越权）。

校验逻辑：裁决主文与申请人仲裁请求集合逐项比对；未决请求强提示，杜绝瑕疵裁决出库。
04 / 权责分立

有权的人确认，系统绝不代行决策

依据仲裁法与仲裁规则，程序权限在秘书、仲裁庭、部门负责人与主任之间严格分立。工作流在每个决策节点设卡（Gate），只有法定有权主体登录后方可点击确认或登记实施。

仲裁秘书 办案中枢

负责立案材料初审、程序路由建议、送达排期管理、证据交换组织以及裁决书草案的程序性核阅比对。

05 / 技术实现

本地优先、数据隔离与事务安全

商事仲裁案件卷宗具有极高保密性。系统在设计上坚持“数据不出域、状态机事务隔离、全链路留痕可溯”。

纯私有化与确定性技术架构

后端基于 Fastify 与 Better-SQLite3 单库架构，所有工作流试跑均基于内存副本（In-memory clone）执行，校验失败立即丢弃，成功且经人工确认后单事务提交，彻底杜绝数据污染。

LOCAL-FIRST EMBEDDING

本地化向量检索与重排

基于 ChromaDB，内嵌 BAAI/bge-small-zh-v1.5 与 bge-reranker 本地模型。案卷材料仅在本地分词与向量化，绝不上传至任何公网第三方。

ACID STATE MACHINE

状态机副本事务机制

工作流运行与人工决策全程 ACID 事务保护。旧版本并发修改由 409 乐观锁拦截，审计日志与操作轨迹全时空留痕。

DAEMON INTEGRATION

launchd 守护与单端口部署

Node 22 + Fastify 单端口同源托管 API 与 Vite 前端 SPA。由 macOS launchd 系统级托管守护，崩溃自动拉起，登录开机自启。
