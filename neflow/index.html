03 / 机制

四大核心设计，兼顾严谨与灵活

中立评估绝非含糊的折衷调解，而是建立在精细技术查明与确定性规则之上的专业研判。

FEATURE 01

逐特征侵权比对

严格贯彻全面覆盖原则。权利要求拆解为独立技术特征，与被诉方案逐项锚点对齐。AI 进行字面相同、等同特征分析与置信度打分，关键疑点由评估庭逐行确认。

无锚点不入稿 · 缺锚点拒绝写入
FEATURE 02

争点树确认回路

A0 先分别为双方卷宗梳理最强论点，再由中立步骤合并生成争点树。争点草案发给双方逐条确认或提出修正，经评估庭锁定后方可进入正式审理。

先双边后中立 · 双方确认后锁定
FEATURE 03

意见时钟硬约束

评估庭接受指定并签发程序指令后，启动确定性意见时钟（默认 50 天）。期限引擎到期前预警；除经双方合意延期或和解暂停外，届满未签发即程序终止。

倒计时控制 · 杜绝无限期拖延
FEATURE 04

独立和解通道

N2–N9 期间任一方均可申请转入和解通道。和解会话与方案存放在独立命名空间，评估专家无法调阅底牌。和解未成则无缝返回原节点，和解材料严格封存。

C8 信息隔离 · 绝不流入后续审理
04 / 通道

当事人与专家分通道参与，各在其位

平台构建了严格的多通道权限隔离体系，当事人和专家在各自清晰的职责边界内展开协作。

PARTIES

当事人端

  • 凭项目案号 + 8 位防混淆验证码独立登录，双边隔离
  • 在线核对申请要素，查阅送达邀请函与程序指令
  • 对争点树逐条确认或修正，在补证回路中对照缺口上传证据
  • 随时发起和解申请，在独立通道中协商和解条款
EXPERT PANEL

评估专家工作台

  • 待确认事项汇总：审定争点树、签发指令、启动意见时钟
  • 逐特征审阅侵权比对表，核实重点审查原因与置信度
  • 组织在线会议评估与技术事实询问，撰写结论并电子签名
  • 审查释疑申请，对笔误或计算疏漏及时出具更正释疑书
ADMIN / SECRETARIAT

平台经办人端

  • 负责立项登记与 1 人 / 3 人评估庭专家组庭与回避排查
  • 审核当事人证据密级（L1 / L2 / L3 及仅律师可见）
  • 排查并拦截疑似提示注入的异常卷宗文件
  • 把关程序推进闸门，经双方明示同意后生成匿名类案索引
05 / 怎么信

从硬约束到审计链，步步可溯

评估意见的客观公信力来自对程序与事实的极致严谨。系统以不可篡改的架构硬约束，保障数据与结论的真实可靠。

C2人工闸门

结论归评估庭

意见书的最终结论只能由评估庭专家亲笔撰写；AI 生成的说理与比对分析一律打上 draft 显式标识，决策权绝不假手模型算法。

C3事实锚点

无锚点不入稿

每项事实认定均附带证据锚点（卷宗编号 + 页码 + 原文字句）；引用的法律条文与司法案例均通过本地权威数据库逐字比对核验。

C5密级分流

涉密材料不上云

涉及核心技术秘密与商业机密的 L3 级证据及「仅律师可见」材料严格留在本地，绝不发往外部模型接口，亦不作为外部检索词。

C6安全隔离

卷宗纯数据原则

卷宗文件被视为不可信的只读数据，任何潜藏在文本或扫描件中的指令均被过滤阻断，杜绝间接提示注入风险。
